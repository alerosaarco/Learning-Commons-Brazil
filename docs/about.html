O que é este projeto?

Este projeto mapeia as 1.710 habilidades da BNCC (Base Nacional Comum Curricular brasileira) ao Learning Commons Knowledge Graph, que organiza os padrões curriculares americanos Common Core (CC) em componentes atômicos de aprendizagem com relações de pré-requisito.

O objetivo é permitir que educadores, pesquisadores e desenvolvedores de EdTech encontrem, para qualquer habilidade da BNCC, quais padrões americanos são equivalentes, quais componentes atômicos de aprendizagem ela exige, e quais habilidades a precedem ou sucedem.

Arquitetura do pipeline

O processo é dividido em 11 etapas, executadas como scripts Python independentes. O Common Core funciona como ponte: em vez de comparar BNCC com CC diretamente, decompõe-se cada currículo em componentes atômicos (uma habilidade por vez, 5–20 palavras, sempre começando com um verbo de ação) e faz-se o matching entre esses componentes.

Etapas 1–2
Coleta e parse da BNCC
As habilidades das três etapas (Educação Infantil, Ensino Fundamental e Ensino Médio) foram extraídas dos JSONs oficiais do MEC, totalizando 1.710 habilidades com código, disciplina, série e descrição em português.
Etapa 3
Tradução da BNCC para inglês
As descrições das habilidades foram traduzidas para inglês com claude-sonnet-4-6 para viabilizar o embedding-based matching com os componentes do CC (que estão em inglês). As descrições originais em português são mantidas para exibição.
Etapa 4
Geração de componentes para padrões CC
Para cada padrão do Common Core sem componentes no Learning Commons, o modelo gerou 3–5 componentes atômicos no mesmo estilo dos componentes existentes do LC (verbo de ação + habilidade específica, 5–20 palavras). Resultado: 10.136 componentes CC.
Etapa 4b
Deduplicação de componentes CC
Componentes quase idênticos dentro de cada padrão CC foram removidos via SequenceMatcher (threshold 0,82). Componentes existentes do LC são mantidos; apenas os gerados por IA são verificados. Removidos: 106.
Etapa 6
Geração de componentes para habilidades BNCC
Em vez de atribuir componentes CC diretamente à BNCC (o que causava combinações inadequadas), o modelo gerou 3–5 componentes independentes por habilidade BNCC, usando componentes CC da mesma disciplina como âncoras de estilo para garantir vocabulário compatível. Resultado: 5.494 componentes BNCC.
Etapa 6b
Deduplicação de componentes BNCC
Mesma lógica da Etapa 4b, aplicada dentro de cada habilidade BNCC. Removidos: 287 componentes quase idênticos.
Etapa 7
Matching componentes BNCC ↔ CC (4 níveis)
Para cada componente BNCC, TF-IDF recupera os 20 componentes CC mais próximos da mesma disciplina (Matemática↔Math, Língua Portuguesa↔ELA, Ciências↔Science). O modelo Claude classifica cada par em um de quatro níveis:

Etapa 8
Similaridade de Jaccard ponderada (BNCC ↔ padrão CC)
Para cada par (habilidade BNCC, padrão CC), calcula-se um score de similaridade com base nos pesos dos componentes correspondentes:
score(H, S) = Σ peso(nível) / (|componentes_BNCC| + |componentes_CC| − Σ peso(nível))

Resultado: 1.372 habilidades (80,2%) possuem ao menos um padrão CC correspondente. As 338 sem correspondência são majoritariamente disciplinas sem equivalente no CC (História, Geografia, Educação Física, Ensino Religioso, Computação).

Etapa 9a
Herança do grafo de pré-requisitos
O Learning Commons define 757 arestas de pré-requisito entre padrões CC — todas dentro da Matemática. Para cada aresta onde ambos os extremos possuem habilidades BNCC mapeadas (score ≥ 0,08 e sem inversão de série), a relação é herdada para o grafo BNCC. Resultado: 290 arestas limpas.

O LC não define pré-requisitos para Língua Inglesa/Portuguesa ou Ciências. Por isso, apenas habilidades de Matemática exibem pré-requisitos neste projeto.
Etapa 10
Tradução de componentes para português
Os 5.373 componentes únicos foram traduzidos para PT-BR com claude-haiku-4-5 em lotes de 50, preservando a estrutura verbo-de-ação + habilidade específica e o vocabulário curricular brasileiro.
Etapa 11
Build do site estático
Um script gera 1.710 arquivos JSON individuais (um por habilidade) e um índice de busca. O site usa Fuse.js para busca semântica fuzzy no cliente, sem servidor ou banco de dados — hospedado inteiramente via GitHub Pages.

Limitações conhecidas

  • Pré-requisitos apenas em Matemática: o Learning Commons só mapeia pré-requisitos para padrões de Matemática. Habilidades de outras disciplinas exibem uma observação explicando a ausência.
  • Habilidades sem correspondência CC (19,8%): disciplinas como História, Geografia e Ensino Religioso são inteiramente brasileiras e não têm equivalente no Common Core americano.
  • Componentes gerados por IA: os componentes atômicos foram gerados por modelos de linguagem e podem conter imprecisões. Os componentes existentes do Learning Commons (fonte: lc_existing) são autoritativos.
  • Habilidades multi-série: habilidades que abrangem múltiplas séries (ex.: EF15AR01 = 1º ao 5º ano) são tratadas como uma unidade única.

Stack técnica

  • Modelos: claude-sonnet-4-6 para geração e matching de componentes; claude-haiku-4-5 para tradução
  • Embedding / retrieval: TF-IDF via scikit-learn (busca de candidatos); Fuse.js (busca no site)
  • Matching: SequenceMatcher para deduplicação; Jaccard ponderada para scoring final
  • Pipeline: Python + pandas + tenacity (retry) + ThreadPoolExecutor (concorrência)
  • Site: HTML/CSS/JS estático + Fuse.js — sem framework, sem servidor, hospedado via GitHub Pages
