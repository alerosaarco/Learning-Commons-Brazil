# BNCC × Learning Commons Mapping — Technical Specification

## Project Goal

Map **every** BNCC (Base Nacional Comum Curricular) habilidade — from Educação Infantil through Ensino Médio, across **all subjects** — to Learning Commons' Knowledge Graph, producing a single inspectable spreadsheet that enables two things:

1. **Pre-requisites**: For any BNCC habilidade, know which other BNCC habilidades are pre-requisites.
2. **Learning Components**: For any BNCC habilidade, know which granular learning components (skills) it requires.

The bridge strategy: **BNCC → Common Core (US) → Learning Commons Knowledge Graph**.

Where Learning Commons does not yet have learning components or pre-requisites for a subject (e.g., Science, History, Geography), the pipeline must **generate them using AI**, following the same structure and granularity as Learning Commons' own components, and clearly tag which data came from Learning Commons vs. AI.

---

## Critical Principles

### 1. Full Scope — No Proof of Concept
This is not a POC. Process **every single BNCC habilidade**:
- Educação Infantil (~200+ objetivos de aprendizagem)
- Ensino Fundamental 1º–9º ano (~1,300+ habilidades)
- Ensino Médio (~400+ habilidades)
- **All subjects**: Matemática, Língua Portuguesa, Ciências, Geografia, História, Arte, Educação Física, Ensino Religioso, and all Ensino Médio areas (Linguagens, Matemática, Ciências da Natureza, Ciências Humanas)

### 2. Inspectability — Step-by-Step Verification
Every step must produce an inspectable output — either a tab in the spreadsheet or a saved CSV. The person reviewing this must be able to:
- See every BNCC standard and its English translation side by side
- See every BNCC → CC match with similarity scores
- See every learning component assignment with yes/no rationale
- See every pre-requisite chain and how it was derived
- See clearly what was sourced from Learning Commons vs. generated by AI

### 3. AI-Generated Components Where Gaps Exist
When Learning Commons does not have learning components for a CC standard (or when a BNCC standard has no good CC match), the pipeline must:
- Generate learning components using Claude API, mimicking Learning Commons' style and granularity
- Tag these as `source: AI-generated` (vs. `source: Learning Commons`)
- Apply the same yes/no filtering logic as for LC-sourced components

### 4. Source Tagging Throughout
Every row that involves AI judgment must carry a `source` column:
- `Learning Commons` — data came directly from the Knowledge Graph
- `AI-generated` — data was created by Claude API
- `AI-matched` — a match or mapping decision made by Claude API
This applies to: learning components, pre-requisites, and CC matches.

## Step-by-Step Implementation

### Step 1: Download and Parse BNCC Standards

**Source**: The official BNCC PDF from `basenacionalcomum.mec.gov.br`

- Main PDF (Educação Infantil + Ensino Fundamental): `https://basenacionalcomum.mec.gov.br/images/BNCC_EI_EF_110518_versaofinal_site.pdf`
- Ensino Médio: `https://basenacionalcomum.mec.gov.br/images/BNCC_20dez_site.pdf`

**Alternative structured source** (may be easier to scrape): `https://curriculo.cieb.net.br/habilidades/bncc` — this site lists all habilidades in a structured, browsable format.

**BNCC Code Structure** (Ensino Fundamental example):
```
EF 05 MA 01
│  │   │   │
│  │   │   └── Sequential skill number (01, 02, ...)
│  │   └────── Subject: MA=Matemática, LP=Língua Portuguesa, CI=Ciências,
│  │           GE=Geografia, HI=História, AR=Arte, EF=Educação Física, ER=Ensino Religioso
│  └────────── Grade: 01-09 (or ranges like 15=1st-5th, 69=6th-9th)
└───────────── Stage: EF=Ensino Fundamental
```

For Educação Infantil:
```
EI 03 ET 01
│  │   │   │
│  │   │   └── Sequential number
│  │   └────── Field of Experience: ET=Espaços/Tempos, CG=Corpo/Gestos,
│  │           TS=Traços/Sons, EO=Escuta/Oralidade, EF=Espaços/Formas
│  └────────── Age Group: 01=Bebês(0-1.5y), 02=Crianças bem pequenas(1.5-3.9y),
│              03=Crianças pequenas(4-5.9y)
└───────────── Stage: EI=Educação Infantil
```

For Ensino Médio:
```
EM 13 LGG 101
│  │   │    │
│  │   │    └── Sequential number (1xx=competência 1, 2xx=competência 2, etc.)
│  │   └─────── Area: LGG=Linguagens, MAT=Matemática, CNT=Ciências da Natureza,
│  │            CHS=Ciências Humanas, LP=Língua Portuguesa
│  └─────────── 13 = can be developed across any Ensino Médio year
└────────────── Stage: EM=Ensino Médio
```

**Output of Step 1**: `data/processed/bncc_standards.csv`

| Field | Description |
|-------|-------------|
| `bncc_code` | e.g., "EF05MA01" |
| `stage` | "EI", "EF", or "EM" |
| `grade` | Grade level or range |
| `subject` | Subject area (full name, e.g., "Matemática") |
| `subject_code` | Short code (e.g., "MA", "LP", "CI") |
| `description_pt` | Original Portuguese text |
| `thematic_unit` | Unidade temática (if available from PDF/scrape) |
| `knowledge_object` | Objeto de conhecimento (if available) |

**Verification**: After this step, output a count by stage × subject and print it to console. The person should be able to confirm all subjects and stages are present.

### Step 2: Download Learning Commons Knowledge Graph

**Source**: GitHub — `https://github.com/learning-commons-org/knowledge-graph`

**Download the JSONL files**:
```bash
# Check CHANGELOG first for latest version
curl -L "https://cdn.learningcommons.org/knowledge-graph/v1.3.0/exports/nodes.jsonl?ref=gh_curl" -o data/raw/nodes.jsonl
curl -L "https://cdn.learningcommons.org/knowledge-graph/v1.3.0/exports/relationships.jsonl?ref=gh_curl" -o data/raw/relationships.jsonl
```

> **IMPORTANT**: Check `https://github.com/learning-commons-org/knowledge-graph/blob/main/CHANGELOG.md` for the latest version before downloading. Update the URL version number accordingly.

**Schema — Key Node Types** (from `nodes.jsonl`):

Each line is a JSON object with `labels` (array), `properties` (object), and `identifier` (UUID).

- **`StandardsFrameworkItem`** — Individual standards (Common Core, state standards)
  - Key properties: `statementCode`, `description`, `jurisdiction`, `academicSubject`, `gradeLevel`, `statementType`
  - Filter for Common Core: `jurisdiction == "Multi-State"`

- **`LearningComponent`** — Granular skills/concepts (developed with ANet)
  - Key properties: `name`, `description`

- **`StandardsFramework`** — The framework itself (e.g., "Common Core State Standards")

**Schema — Key Relationship Types** (from `relationships.jsonl`):

Each line is a JSON object with `type`, `startIdentifier`, `endIdentifier`, and `properties`.

- **`isChildOf`** — Standard hierarchy (e.g., a standard is child of a cluster/domain)
- **`hasLearningComponent`** — Links a StandardsFrameworkItem to its LearningComponents
- **`isPrerequisiteOf`** / **`hasPrerequisite`** — Pre-requisite relationships between standards (from SAP Coherence Map)
- **`isRelatedTo`** — Cross-standard alignment
- **`relevantToStandard`** — Links a Factor to a StandardFrameworkItem (used for ELA)

**Extracting what we need**:

```bash
# Extract ALL Common Core standards (not just math — we need all subjects)
jq -c 'select((.labels | contains(["StandardsFrameworkItem"])) and .properties.jurisdiction == "Multi-State")' nodes.jsonl > data/processed/cc_all_standards.jsonl

# Extract Learning Components
jq -c 'select(.labels | contains(["LearningComponent"]))' nodes.jsonl > data/processed/learning_components.jsonl

# Extract ALL relevant relationships
jq -c 'select(.type == "hasLearningComponent" or .type == "isPrerequisiteOf" or .type == "hasPrerequisite" or .type == "relevantToStandard")' relationships.jsonl > data/processed/relevant_relationships.jsonl
```

**Output of Step 2**: Parsed and indexed data structures, saved as CSVs:
- `data/processed/cc_standards.csv` — all CC standards with UUID, code, description, grade, subject
- `data/processed/learning_components.csv` — all LCs with UUID, name, description
- `data/processed/cc_to_lc_mapping.csv` — which CC standards have which LCs
- `data/processed/cc_prerequisites.csv` — which CC standards are prerequisites of which

**Verification**: Print to console:
- Count of CC standards by subject (Math, ELA, Science, etc.)
- Count of learning components total
- Count of CC standards that HAVE learning components vs. those that DON'T
- Count of CC standards with pre-requisite data vs. those without
- This tells us exactly where Learning Commons has coverage and where AI will need to fill gaps.

### Step 3: Translate BNCC to English

For each BNCC habilidade, translate `description_pt` to English using Claude API.

**Claude API batch translation prompt**:
```
You are translating Brazilian educational standards (BNCC) to English.
Translate the following BNCC habilidade descriptions from Portuguese to English.
Preserve educational terminology precisely. For example:
- "grandezas e medidas" → "measurement and data" (not "magnitudes and measures")
- "números racionais" → "rational numbers"
- "leitura e escrita" → "reading and writing"
- "produção de textos" → "text production / writing"
Return ONLY a JSON array of translated strings, in the same order as the input.
No additional text.

Input descriptions:
[JSON array of Portuguese descriptions]
```

**Batch size**: ~20 descriptions per API call.

**Checkpointing**: Save after every batch. If interrupted, resume from the last completed batch.

**Output of Step 3**: `data/processed/bncc_translated.csv` — same as Step 1 output, with an added `description_en` column.

**Verification**: The `BNCC_Standards` tab in the final spreadsheet will show `description_pt` and `description_en` side by side for human review.

### Step 4: Map BNCC → Common Core (1-3 matches per BNCC standard)

For each BNCC habilidade (in English), find the 1-3 most similar Common Core standards.

**Subject mapping** (BNCC subject → CC subject for candidate filtering):

| BNCC Subject | CC Subject(s) to search |
|-------------|------------------------|
| Matemática (MA) | Mathematics |
| Língua Portuguesa (LP) | English Language Arts |
| Ciências (CI) | Science (NGSS if available in LC) |
| Geografia (GE) | Social Studies / ELA (cross-curricular) |
| História (HI) | Social Studies / ELA (cross-curricular) |
| Arte (AR) | ELA (closest available) |
| Educação Física (EF) | No direct CC match — flag for AI-only |
| Ensino Religioso (ER) | No direct CC match — flag for AI-only |
| EM: Linguagens (LGG) | English Language Arts |
| EM: Matemática (MAT) | Mathematics |
| EM: Ciências da Natureza (CNT) | Science |
| EM: Ciências Humanas (CHS) | Social Studies / ELA |
| EI: All fields | K-level CC standards (cross-subject) |

For subjects with no direct CC equivalent (Educação Física, Ensino Religioso), the mapping step should still attempt a best-effort match but flag `cc_match_quality: "no-direct-equivalent"`. Learning components for these will be fully AI-generated in Step 5.

**Approach — Claude API for matching** (recommended for accuracy):

```
You are an education standards alignment expert.

BNCC Standard (Brazil):
Code: [bncc_code]
Grade: [grade]
Subject: [subject]
Description (EN): [description_en]

Candidate Common Core standards (US) — same subject area, grades ±2:
[numbered list of CC code: description]

Which 1-3 Common Core standards best match the BNCC standard?
For each match, provide a confidence score (0.0 to 1.0).
If none are a good match (all below 0.4), return an empty array.

Return ONLY JSON: [{"cc_code": "...", "score": 0.85, "rationale": "brief reason"}, ...]
```

**Grade mapping heuristic** (BNCC → US grades):

| BNCC | US Equivalent |
|------|--------------|
| EI (Bebês, 0-1.5y) | Pre-K |
| EI (Crianças bem pequenas, 1.5-3.9y) | Pre-K |
| EI (Crianças pequenas, 4-5.9y) | K |
| EF 1º ano | Grade 1 |
| EF 2º–5º ano | Grades 2–5 |
| EF 6º–9º ano | Grades 6–8 |
| EM (all) | Grades 9–12 / HS |

**Output of Step 4**: `data/processed/bncc_cc_mapping.csv`

| Column | Description |
|--------|-------------|
| `bncc_code` | BNCC standard |
| `cc_code` | Matched CC code |
| `cc_description` | CC standard text |
| `similarity_score` | Match confidence (0-1) |
| `match_rationale` | Brief reason for match |
| `match_rank` | 1, 2, or 3 |
| `cc_match_quality` | "direct", "partial", or "no-direct-equivalent" |
| `source` | "AI-matched" |

**Verification**: Every match includes a `match_rationale` column so the reviewer can understand WHY a match was made.

### Step 5: Assign Learning Components (LC-sourced or AI-generated)

For each BNCC standard and its 1-3 CC matches:

**Path A — Learning Commons has components for the CC standard:**
1. Look up learning components via `hasLearningComponent` relationships.
2. Tag these as `source: Learning Commons`.

**Path B — Learning Commons does NOT have components for the CC standard:**
1. Generate learning components using Claude API.
2. Tag these as `source: AI-generated`.

**AI generation prompt for Path B**:
```
You are an education curriculum expert creating learning components.

Learning components are granular, teachable sub-skills that together compose mastery of a standard. They should be:
- Specific and measurable
- Typically 3-7 components per standard
- Written as concise skill statements (e.g., "Identify the numerator and denominator of a fraction")
- At a finer grain than the standard itself

Here are examples of real Learning Commons components for reference:
[include 5-10 real LC examples from math to show style/granularity]

Standard to decompose:
BNCC Code: [bncc_code]
Description (EN): [description_en]
Matched CC Code: [cc_code] (if any)
CC Description: [cc_description] (if any)

Generate 3-7 learning components for this standard.
Return ONLY JSON: [{"name": "short name", "description": "full description"}, ...]
```

**Then, for ALL components (both paths), apply the yes/no filter**:

```
BNCC Standard: [bncc_code] — [description_en]

Learning Components:
1. [name]: [description]
2. [name]: [description]
...

For each learning component, determine if it is REQUIRED to master this specific BNCC standard.
Return ONLY JSON: [{"component_index": 1, "required": "YES", "reason": "brief reason"}, ...]
```

**Output of Step 5**: `data/processed/bncc_learning_components.csv`

| Column | Description |
|--------|-------------|
| `bncc_code` | BNCC standard |
| `learning_component_id` | UUID (LC's own ID) or generated ID (e.g., `AI-EF05MA01-001`) |
| `learning_component_name` | Short name |
| `learning_component_description` | Full description |
| `required` | YES / NO |
| `required_reason` | Brief rationale for the yes/no decision |
| `source_cc_code` | Which CC standard this LC came from (or "none" if AI-generated without CC match) |
| `source` | `Learning Commons` or `AI-generated` |

**Verification**: The `required_reason` column lets the reviewer understand every yes/no decision. The `source` column makes LC vs. AI immediately filterable.

---

### Step 6: Determine Best Single CC Match

For each BNCC standard, among its 1-3 CC candidates from Step 4, select the **single best match** based on:

1. **Learning component overlap** (from Step 5): the CC standard whose "YES" components best cover the BNCC standard.
2. **Original similarity score** from Step 4 as tiebreaker.

Formula:
```
best_match_score = (count_of_yes_components / total_components) * 0.7 + similarity_score * 0.3
```

If a BNCC standard had NO CC matches in Step 4, mark `best_cc_match` as `"NONE"`.

**Output of Step 6**: `data/processed/bncc_best_cc_match.csv`

| Column | Description |
|--------|-------------|
| `bncc_code` | BNCC standard |
| `best_cc_code` | Best CC match (or "NONE") |
| `best_cc_description` | CC description |
| `match_score` | Combined score |
| `components_yes` | Count of YES components |
| `components_total` | Total components evaluated |
| `match_quality` | "direct", "partial", "no-direct-equivalent", or "none" |

---

### Step 7: Map Pre-requisites Back to BNCC

**Path A — Learning Commons has pre-requisites for the CC standard:**
1. Get `best_cc_match` for the BNCC standard.
2. Look up CC pre-requisites via `isPrerequisiteOf` / `hasPrerequisite`.
3. Reverse-map each CC pre-requisite back to a BNCC standard (using the best_cc_match reverse index from Step 6).
4. Tag as `source: Learning Commons`.

**Path B — Learning Commons does NOT have pre-requisites (or BNCC has no CC match):**
1. Use Claude API to infer pre-requisites.
2. Tag as `source: AI-generated`.

**AI generation prompt for Path B**:
```
You are an education curriculum sequencing expert.

Given this BNCC standard:
Code: [bncc_code]
Grade: [grade]
Subject: [subject]
Description (EN): [description_en]

And the full list of BNCC standards for the same subject in earlier grades:
[list of bncc_code: description_en, filtered to same subject and lower/equal grades]

Which of these earlier standards are direct pre-requisites for mastering the given standard?
A pre-requisite is a skill that MUST be mastered before the student can learn the target standard.
Only include direct pre-requisites (not transitive ones).

Return ONLY JSON: [{"prerequisite_bncc_code": "...", "reason": "brief reason"}, ...]
If the standard is foundational (grade 1 or EI) with no pre-requisites, return [].
```

**Output of Step 7**: `data/processed/bncc_prerequisites.csv`

| Column | Description |
|--------|-------------|
| `bncc_code` | BNCC standard |
| `bncc_description_en` | For readability |
| `prerequisite_bncc_code` | Pre-requisite BNCC standard |
| `prerequisite_description_en` | For readability |
| `prerequisite_reason` | Why this is a pre-requisite |
| `via_cc_code` | CC bridge code (if Path A) or "N/A" (if Path B) |
| `via_cc_prerequisite_code` | CC pre-req bridge code (if Path A) or "N/A" |
| `source` | `Learning Commons` or `AI-generated` |

### Step 8: Assemble Final Spreadsheet

Create a single `.xlsx` file. Claude Code should define the final tab structure, but these are the **minimum required tabs**:

**Tab: `BNCC_Standards`** — Master list. Every BNCC standard with its translation and best CC match.
- `bncc_code`, `stage`, `grade`, `subject`, `subject_code`, `description_pt`, `description_en`, `thematic_unit`, `knowledge_object`, `best_cc_match`, `best_cc_description`, `match_score`, `match_quality`

**Tab: `CC_Mapping`** — Full BNCC-to-CC mapping (all 1-3 candidates per standard).
- `bncc_code`, `cc_code`, `cc_description`, `similarity_score`, `match_rationale`, `match_rank`, `is_best_match`, `cc_match_quality`, `components_yes`, `components_total`, `source`

**Tab: `Learning_Components`** — Every BNCC standard × learning component pair.
- `bncc_code`, `bncc_description_en`, `learning_component_id`, `learning_component_name`, `learning_component_description`, `required`, `required_reason`, `source_cc_code`, `source`

**Tab: `Prerequisites`** — Every BNCC standard × pre-requisite pair.
- `bncc_code`, `bncc_description_en`, `prerequisite_bncc_code`, `prerequisite_description_en`, `prerequisite_reason`, `via_cc_code`, `via_cc_prerequisite_code`, `source`

**Tab: `Unmapped`** — Standards or pre-reqs that couldn't be fully mapped.
- `bncc_code`, `issue_type` (e.g., "no CC match", "CC prereq has no BNCC reverse match"), `details`, `cc_code_if_applicable`

**Tab: `Coverage_Summary`** — High-level stats to validate completeness.
- Total BNCC standards by stage × subject
- Count with CC matches / without
- Count with LC-sourced components / AI-generated components
- Count with LC-sourced pre-reqs / AI-generated pre-reqs
- Coverage percentages
- Average components per standard (LC vs. AI)
- Average pre-requisites per standard (LC vs. AI)

**Tab: `Source_Audit`** — Aggregated view of source tagging across the dataset.
- By subject: % Learning Commons vs. % AI-generated for components and pre-reqs
- Lets the reviewer know exactly where to focus human QA

Claude Code may add additional tabs if useful (e.g., a `Translation_Review` tab showing PT/EN side by side, or a `Component_Library` tab listing all unique learning components). The principle is: **make every decision inspectable**.

## Known Limitations & Risks

1. **Learning Components coverage**: As of early 2026, Learning Commons has learning components primarily for **math**. ELA has "Factors" (via `relevantToStandard`) which should be used where available. For all other subjects, components will be AI-generated.

2. **Pre-requisites coverage**: The SAP Coherence Map in Learning Commons covers **math only**. For all other subjects, pre-requisites will be AI-generated based on grade sequencing and skill logic.

3. **BNCC ≠ Common Core**: The Brazilian curriculum has unique emphases (financial education, biodiversity, Brazilian geography/history). Some standards will have no good CC match. These are handled via AI-generated components rather than being forced into a bad match.

4. **Translation quality**: Semantic matching depends on translation quality. The prompt includes terminology guidance, but edge cases may occur. The side-by-side PT/EN display in the spreadsheet enables human review.

5. **AI consistency**: AI-generated components may vary in granularity. Using few-shot examples from real LC components helps, but some variation is expected. The `source` tag allows filtering and targeted QA.

6. **Version pinning**: Record the BNCC PDF version (date) and Learning Commons version (e.g., v1.3.0) in the `Coverage_Summary` tab.

7. **API costs**: With ~1,900 standards and multiple API calls per standard (translation, matching, component generation, filtering, pre-requisite generation), budget for approximately 5,000-10,000 Claude API calls. Use Sonnet for all calls (best cost/quality ratio).
